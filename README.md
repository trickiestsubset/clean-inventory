# Clean Inventory

A small, QR-code-based inventory app. Every location (a shelf, bin, drawer,
van...) gets a QR code. Scan it on your phone and you can see everything
stocked there, pull parts out, or add parts in — no app install needed, it's
just a website.

Built to run for free on [Vercel](https://vercel.com) (hosting) +
[Supabase](https://supabase.com) (database + photo storage), both of which
have generous free tiers that comfortably cover a small inventory like this.

## What it does

- **Locations** — create a location, get a QR code for it instantly. Print
  the QR code and stick it on the shelf/bin/drawer.
- **Scan a location** — opens a page showing every part stocked there and
  its quantity. Pull stock (subtract), add stock (add), add an existing part
  to that location, or register a brand new part right there (with a photo
  taken from your phone).
- **Parts catalog** — every part has a name, optional SKU, description, and
  photo. See the total quantity across all locations, and which specific
  locations have it.
- **Search** — the home page lets you search for a part by name/SKU and see
  every location that has it.
- **Shared passcode** — the whole site is locked behind one shared passcode
  (no individual user accounts to manage).

## 1. Create a Supabase project (free)

1. Go to [supabase.com](https://supabase.com) and create a free account and
   a new project. Pick any name/region; save the database password it gives
   you somewhere safe (you probably won't need it again).
2. Once the project is ready, open **SQL Editor** in the left sidebar, paste
   in the entire contents of [`supabase/schema.sql`](./supabase/schema.sql)
   from this project, and click **Run**. This creates the tables and a
   helper function.
3. Open **Storage** in the left sidebar → **New bucket** → name it exactly
   `part-photos` → toggle **Public bucket** on → **Create bucket**. This is
   where part photos are stored.
4. Open **Project Settings → API**. You'll need two values from here in the
   next step:
   - **Project URL** (looks like `https://xxxxx.supabase.co`)
   - **service_role** key, under "Project API keys" (⚠️ keep this secret —
     it has full access to your database, and is only ever used from the
     server side of this app, never the browser)

## 2. Put the code on GitHub

Vercel deploys straight from a GitHub repo. If you don't already have this
project on GitHub:

```bash
cd clean-inventory
git init
git add .
git commit -m "Initial commit"
```

Then create a new (private is fine) repository on GitHub and push:

```bash
git remote add origin https://github.com/<your-username>/clean-inventory.git
git branch -M main
git push -u origin main
```

## 3. Deploy to Vercel (free)

1. Go to [vercel.com](https://vercel.com), sign up (GitHub login is easiest),
   and click **Add New → Project**. Pick the `clean-inventory` repo you just
   pushed.
2. Before clicking Deploy, open **Environment Variables** and add:

   | Name | Value |
   |---|---|
   | `SUPABASE_URL` | your Supabase Project URL |
   | `SUPABASE_SERVICE_ROLE_KEY` | your Supabase service_role key |
   | `SUPABASE_PHOTO_BUCKET` | `part-photos` |
   | `APP_PASSCODE` | whatever passcode you want people to type in |
   | `SESSION_SECRET` | a long random string — generate one with `openssl rand -hex 32` in a terminal |

3. Click **Deploy**. After a minute or two you'll get a live URL like
   `clean-inventory-yourname.vercel.app` — open it, enter your passcode, and
   try it out.

## 4. Point cleaninventory.site.je at it

1. In the Vercel project, go to **Settings → Domains** and type in
   `cleaninventory.site.je` (and optionally `www.cleaninventory.site.je`) →
   **Add**.
2. Vercel will show you one or two DNS records to add (typically an `A`
   record for the bare domain and/or a `CNAME` for `www`, pointing at
   Vercel). Log in to wherever `site.je` is registered/managed, open its DNS
   settings, and add exactly the records Vercel shows you.
3. DNS changes can take anywhere from a few minutes to a few hours to take
   effect. Vercel's Domains page will show a green checkmark once it's live
   and will automatically issue a free HTTPS certificate for it.

Once that's done, `https://cleaninventory.site.je` is your app, and QR codes
generated by the app will automatically use whatever domain you scan them
from.

## Day to day use

- **Add a location**: go to **Locations → Add a location**, give it a name
  (e.g. "Shelf A3"). A QR code is generated instantly. Use **Print all QR
  labels** to print all of them at once, cut them out, and stick them on
  the shelves/bins.
- **Scan a location**: point any phone camera at the QR code — it opens
  straight to that location's page (after the passcode, the first time).
- **Pull / add stock**: on a location page, each part has a small quantity
  box and Pull/Add buttons.
- **New part on the spot**: on a location page, use "Add a brand new part" —
  you can snap a photo right there with your phone.
- **Find a part**: use the search box on the home page, or browse **Parts**.

## Running it locally (optional, for development)

```bash
npm install
cp .env.example .env.local   # then fill in the values from steps 1 above
npm run dev
```

Open http://localhost:3000.

## Notes

- This app talks to Supabase only from the server (never the browser), using
  the service role key, and locks every table down with row-level security.
  The shared passcode is checked server-side and stored as a signed,
  http-only cookie.
- `npm audit` will flag a batch of Next.js advisories against the 14.x
  line — most describe self-hosting/edge-case scenarios (custom servers,
  i18n routing, CSP nonces) that don't apply to this app's setup on Vercel
  behind a passcode. Worth revisiting with a Next.js upgrade once the app
  has been in use for a while and you want to invest in it further.
- Costs: Vercel's free "Hobby" tier and Supabase's free tier are both meant
  for exactly this kind of small, low-traffic project. If it ever
  outgrows the free tiers (a lot more traffic, more storage), both have
  simple paid plans to move to your own account.
